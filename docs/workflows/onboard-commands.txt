PX4 onboard SE3 example — command contexts
=========================================

Use the complete workflow in operations/onboard.md and the interface reference
in operations/tools.md. These commands are separate steps, not an unattended
flight script. Physical flight validation is not established.

UBUNTU REPOSITORY SHELL ($)
--------------------------
# Start the installed environment (choose one):
./tools/sitl start
# On a configured physical companion instead: ./tools/hardware start

# Local catalog/compilation does not connect to PX4:
./tools/trajectory list
./tools/trajectory compile full_excitation

# With the correct PX4 connected and DISARMED, apply the simulator profile:
./tools/onboard_params load se3 gz_f450
# gz_f450 requires SYS_AUTOSTART=4022. Do not use it for a physical aircraft.
# A hardware .parm must contain verified vehicle values; .parm.example is not
# loadable and starting the runtime never applies a profile automatically.

# Compile and upload over independent MAVLink FTP, DISARMED:
./tools/trajectory upload full_excitation
# The baseline helix_r05 entry is inconsistent, so --all fails validation.
# Cleanup is optional and DELETES local/remote .traj catalog files:
# ./tools/trajectory clean

# In a dedicated repository shell, start DDS recording before mode selection:
source ros2/runtime_env.sh
./tools/px4_record onboard_se3
# This remains in the foreground. After landing use Ctrl-C, or in another shell:
# ./tools/px4_record status
# ./tools/px4_record stop

PX4 SHELL (pxh> in SITL; hardware px4-shell window is a MAVLink Shell)
-------------------------------------------------------------------
# Inspect the initialized module, catalog, and native logger:
se3_control status
trajectory list
logger status

# After pilot-controlled Position-mode takeoff and verified stable hover:
se3_control select
se3_control status
# Require accepted mode entry and holding; verify absolute plan origin/heading.
trajectory start full_excitation
se3_control status
# Optional interruption captures the measured current pose in SE3 mode:
# se3_control hold

# Follow the operating procedure to return to pilot control and land.
# Do not stop environment services or disarm an airborne aircraft.
# After landed/disarmed, inspect/finalize native logging if needed:
logger status
# logger stop

ANALYSIS WORKSTATION — UBUNTU REPOSITORY SHELL ($)
-------------------------------------------------
# After ROS-bag finalization, on a host with analysis dependencies:
source ros2/runtime_env.sh
./tools/px4_analyze bags/onboard_se3/<recording-directory>
# Obtain completed ULogs manually using PX4/QGroundControl facilities:
./tools/px4_analyze /path/to/flight.ulg --profile onboard_se3
# For multi-run logs select the actual run ID:
# ./tools/px4_analyze /path/to/flight.ulg --profile onboard_se3 --run-id 1

CONNECTION AND DATA NOTES
-------------------------
- MAVLink Router owns the PX4 MAVLink connection independently of the GCS/DDS.
- It serves the PX4 shell at local port 14661 and transfer clients at 14662.
- Hardware MAVLink and DDS must use separate serial devices.
- Only one toolkit router can use these same local ports on a host at a time.
- Upload does not arm, change mode, or execute a plan.
- Mode selection captures/holds entry pose; explicit trajectory start uses
  absolute PX4 local NED coordinates immediately, without alignment/proximity guard.
- Completion holds the final reference; it does not land or disarm.
- ULog run IDs, phases, and plan CRCs are not present in the standalone DDS bag.
- File sizes in FTP listings are bytes, not flight durations; ULog dropouts are
  missing log data. Preserve log/configuration identity when copying recordings.
